## Cómo Contribuir (Español)

**Gray Notation** es un sistema vivo y abierto. Todas las contribuciones son bienvenidas, desde correcciones tipográficas y mejoras de traducción hasta la propuesta de nuevos símbolos o casos de estudio reales.

### 1. ¿De qué formas puedes colaborar?

* **Proponer nuevos símbolos o convenciones:** Si encontraste un caso de uso en tus clases que los símbolos actuales no cubren bien, abre un *Issue* describiendo:
  1. **El problema analógico:** ¿Qué dificultad tuviste al tomar apuntes?
  2. **El símbolo propuesto:** Debe ser monocromático, rápido de trazar a mano alzada y visualmente distinguible de los símbolos existentes.
  3. **Ejemplo de uso:** Un boceto o foto en papel mostrando cómo se ve en contexto.
* **Compartir apuntes reales (Casos de Estudio):** Puedes aportar fotos o escaneos de tus propios apuntes aplicando Gray Notation para la sección de [Ejemplos Reales](es/Ejemplos-Reales/README.md).
* **Mejorar la documentación y traducciones:** Corregir errores gramaticales, mejorar la claridad de las explicaciones o mantener sincronizadas las versiones en español (`es/`) e inglés (`en/`).

### 2. Estándares de Estilo de la Documentación

Si envías un *Pull Request* modificando archivos `.md`, por favor respeta las siguientes convenciones del proyecto:

1. **Estructura de encabezados:**
   * Cada documento debe tener un único título principal `# H1` numerado (ej. `# 2. Conceptos Básicos`).
   * Las secciones principales deben usar `## H2` y las subsecciones `### H3`.
2. **Barras de navegación:**
   * Mantén la barra de ruta (*breadcrumb*) en la parte superior del documento y los enlaces de navegación (`← Anterior | Siguiente →`) al pie de página.
3. **Compatibilidad Markdown estándar:**
   * Evita usar sintaxis exclusiva de plugins de Obsidian (como `[[Wikilinks]]` o redimensionamiento con `|685` en imágenes). Usa enlaces e imágenes Markdown estándar para garantizar la visualización correcta en GitHub.
4. **Sincronización bilingüe:**
   * Si agregas o modificas un concepto en `es/`, intenta reflejar el cambio equivalente en `en/` (o indícalo en tu *Pull Request* para que podamos ayudar con la traducción).

## How to Contribute (English)

**Gray Notation** is a living, open system. All contributions are welcome, from typo fixes and translation improvements to proposing new symbols or real-world case studies.

### 1. Ways to Contribute

* **Propose new symbols or conventions:** If you encountered a note-taking scenario in your classes that current symbols do not cover well, open an *Issue* describing:
  1. **The analog problem:** What specific difficulty did you face while taking notes?
  2. **The proposed symbol:** It must be monochromatic, quick to draw freehand with a single pen/pencil, and visually distinct from existing symbols.
  3. **Usage example:** A sketch or photo on paper showing how it looks in context.
* **Share real notes (Case Studies):** You can contribute photos or scans of your own notes using Gray Notation for the [Real Examples](en/Real-Examples/README.md) section.
* **Improve documentation and translations:** Fix typos, improve explanation clarity, or help keep the Spanish (`es/`) and English (`en/`) manuals in sync.

### 2. Documentation Style Standards

If you submit a *Pull Request* modifying `.md` files, please follow these project conventions:

1. **Heading Hierarchy:**
   * Each document must have a single numbered `# H1` main title (e.g., `# 2. Basic Concepts`).
   * Main sections must use `## H2` and subsections `### H3`.
2. **Navigation Bars:**
   * Keep the top breadcrumb navigation bar at the start of the file and the sequential links (`← Previous | Next →`) at the bottom.
3. **Standard Markdown Compatibility:**
   * Avoid Obsidian-only syntax (such as `[[Wikilinks]]` or image pipe resizing like `|685`). Use standard Markdown links and image syntax so files render properly on GitHub.
4. **Bilingual Sync:**
   * If you add or update a concept in `en/`, please try to update the corresponding file in `es/` as well (or mention it in your *Pull Request* so maintainers can assist with translation).
